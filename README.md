# ほんとかな？ 思い込みさがし（プロトタイプ）

アキネーター風の質問に答えると、本人が気づかずに信じているかもしれない疑似科学・思い込みを見つけて、
「そう感じるのは自然な理由（認知バイアス）」→「実際にわかっていること」→「参考リンク」の順に紹介する静的Webアプリです。

- サーバー・API・LLM 不要（HTML / CSS / JS + JSON のみ）
- 回答はブラウザ内だけで処理し、どこにも送信しません
- 参考：[Gijika.com](https://gijika.com/)、[錯思コレクション100](https://www.jumonji-u.ac.jp/sscs/ikeda/cognitive_bias/)（文章は転載せず、オリジナルの解説＋リンク）

## 動かし方

`fetch` で JSON を読むため、`index.html` を直接開く（file://）と動きません。ローカルサーバー経由で開いてください。

```bash
python -m http.server 8000
```

→ http://localhost:8000/

### GitHub Pages で公開

リポジトリに push → Settings → Pages → Branch を `main` / `(root)` に設定するだけです。ビルド不要。

### 結果のシェア

結果画面に X / LINE / テキストコピー /（スマホでは）OS標準の共有ボタンがあります。送られるのは「見つかった数・心のクセNo.1・予想の的中数」とページURLだけで、個々の回答は含みません。

### アクセス集計（GoatCounter）

集計ページ：https://hontokana.goatcounter.com （ログインが必要）

- ページの閲覧数・参照元（X・ブログなど）・端末の種類
- ボタン操作の回数：`event/start`（挑戦する）、`event/finish`（結果まで到達）、`event/finish-early`（途中で結果を見た）、`event/more`（もっと質問に答える）、`event/share-x` / `share-line` / `share-copy` / `share-native`（シェア）

Cookieは使わず、個人も特定しません。回答内容や診断結果は送りません。localhost では自動的に数えません。
計測を止めたいときは、`index.html` 末尾の GoatCounter の `<script>` を消すだけです（`track()` は読み込まれていなければ何もしません）。

## データ形式（data/items.json）

```jsonc
{
  "biases": {               // 認知バイアス辞書（複数項目から参照）
    "confirmation": {
      "name": "確証バイアス",
      "catch": "キャッチコピー（オリジナル）",
      "explain": "解説（オリジナル）",
      "link": { "label": "...", "url": "..." }
    }
  },
  "items": [
    {
      "id": "hydrogen_water",
      "type": "pseudoscience",     // pseudoscience | bias
      "title": "結果画面で初めて明かす名前",
      "question": "名前を出さずに信念そのものを聞く質問文",
      "polarity": 1,               // 1: 「はい」=信じている / -1: 「いいえ」=信じている（逆転質問用）
      "tags": ["health", "product"],
      "biases": ["post_hoc", "placebo"],   // biases 辞書のキー
      "empathy": "寄り添いの一言（そう感じるのは自然）",
      "facts": ["実際の知見1", "実際の知見2"],
      "links": [{ "label": "...", "url": "..." }],
      "related": ["minus_ion", "detox"]    // 関連項目の id
    }
  ]
}
```

結果カードの構成は `type` で変わります。

- `pseudoscience`：①そう感じるのは自然なこと（`empathy`＋関係する `biases`）→ ②実際にわかっていること → ③リンク
- `bias`：①この心のクセとは（`biases[0]` の説明）→ ②そう感じるのは自然なこと → ③知っておくと役立つこと → ④リンク
  - `bias` 型の `biases` は**そのクセ1つだけ**にする。別のバイアスを並べると、何の説明かわかりにくくなるため

キャッチコピー（`catch`）は表示時に「」で囲むので、中で引用するときは『』を使ってください。

項目を増やすときは `items` に1件足すだけです。`related` と `biases` は存在するキーを指定してください。

## 出題アルゴリズム

1. 各項目に小さなランダム値（jitter）を初期優先度として与える
2. 回答ごとに「信念スコア」＝ 回答値（はい 1 / たぶんはい 0.5 / わからない 0 / たぶんいいえ -0.5 / いいえ -1）× `polarity` を出す
3. 信念スコアが正なら、他の項目の優先度を加算
   - `related` に含まれる項目：+1.0
   - 共通するバイアス1つにつき：+0.4
   - 共通するタグ1つにつき：+0.15
   - 負の場合は同じ計算に 0.3 を掛けて少しだけ下げる
4. 未出題の中で優先度が最大の項目を次に出す。ただし同じ向き（polarity）の質問が3問続いたら、逆向きの質問を優先する
5. 10問で結果表示（「もっと質問に答える」で続行可）。信念スコア 0.5 以上を「当てはまった」とする

### ゲーム要素

- **ホントカナ**（[js/mascot.js](js/mascot.js)）：案内役。表情は idle / think / hunch / smug / happy / surprised の6種類。セリフは `LINES` に場面ごとにまとめてあり、同じセリフが続けて出ないようにしている
  - 回答へのリアクション：はい系 / たぶんはい / いいえ系 / たぶんいいえ / わからない / ピン度が高いとき / 同じ向きの回答が3問続いたとき
  - 予想：出だし6種類 × 言い回し5種類。的中 / ちょっと当たり / ハズレ / はぐらかし（わからない）、連続的中・連続ハズレ
  - 進み具合：折り返し・ラスト1問（延長ラウンドでもそのラウンドの中で数える）
  - あいさつ：初回 / 2回目以降（図鑑の進み具合）/ 図鑑コンプリート
  - 結果：見つかった数に応じたひとこと
  - キャラクターをタップするとひとこと
- **ピン度メーター**：未出題項目の最大関連度 ÷ `guessThreshold`（`engine.hunch()`）
- **予想**：次に出す項目の関連度（jitter除く）が `guessThreshold`（1.2）以上なら、質問の代わりに「あなた、『{guess}』って思っていませんか？」と先回りする。最初の2問と、予想の直後2問は出さない。回答（当たり / ちょっと当たり / わからない / ハズレ）は `answerGuess` で polarity を考慮して通常の回答に変換される
  - 各項目の `guess` は、その思い込みを短い断定文で書く（例：「血液型で、性格はある程度わかる」）
- **結果発表**：思い込みの数をカウントアップ → 「心のクセ No.1」（当てはまった項目のバイアスを信念スコアで集計）と予想の的中率（ホントカナ vs あなた）
- **心のクセ図鑑**：見つかったバイアスを `localStorage`（`hontokana.zukan.v1`）に貯める。保存できない環境でも本体は動く

### 「全部はい」対策

- 36項目中12項目は逆転質問（`polarity: -1`、「はい」＝正しい理解）。何も考えずに全部「はい」を押すと、逆転質問は「見抜けていた」側に分類される
- 5問以上答えて9割以上が同じ答えなら、結果画面に「ほとんど『はい』で答えていたようです」と注意を表示する
- 質問文は、信じている人が素直に「はい」と答えられる自然な言い方にし、結論が見え透く表現（例：「放射能まで減る」）は避ける。そうした具体的な主張は結果画面の解説で扱う

重みは `js/engine.js` の `DEFAULT_CONFIG` で調整できます。「戻る」は回答履歴から優先度を再計算するので、順序が崩れません。

## 将来のAI組み込み

`createEngine(data, { selector, explainer })` で2箇所を差し替えられるようにしてあります。

- **selector**：次の質問を選ぶ関数。`{ items, priorities, askedIds, answers, config }` を受け取り項目を返す。
  例：LLMで回答傾向から次の項目を選ぶ、質問文を言い換える。
- **explainer**：結果の解説を作る関数。`{ item, biases, answerKey }` を受け取り `{ empathy, biases, facts, links }` を返す。
  例：JSONの事実を土台に、ユーザーの回答に合わせて語り口を調整する（事実部分は JSON を正とし、LLMには言い換えのみさせる設計が安全）。

どちらも既定はルールベースなので、AIなしでもそのまま動きます。
（非同期処理にする場合は `app.js` の `renderQuestion` / `renderResult` を `await` 対応にしてください。）

## 方針・注意

- 口調は否定せず「そう感じるのは自然だけど、実際は〜」の寄り添い型
- 政治的な陰謀論は対象外
- 健康・治療に関する項目は、医師・公的機関への相談を促す一文を入れる
- 解説はプロトタイプ用に書いたもの。公開前に専門家のレビューとリンク切れチェックを推奨
